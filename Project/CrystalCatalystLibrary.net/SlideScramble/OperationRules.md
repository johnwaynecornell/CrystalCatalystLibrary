# Operation and rule architecture

`IPuzzleOperation` resolves an immutable `IOperationIntent` against an `OperationBoardSnapshot`. It returns an `OperationResolution` containing a stable operation ID and an ordered expansion in the existing `RecordedMove` row/column primitives. Resolution is deterministic and does not apply moves. The default registry includes Slide, Shuffle, ColumnSwap and RowSwap resolvers.

`PuzzleRuleSet` snapshots three separate ID sets: `ScrambleAllowed`, `SolveAllowed`, and `UIEnabled`. The first two are mathematical rules; `UIEnabled` is the initial live input configuration, not a permanent permission. The default constructor creates classic SlideScramble rules. Duplicate IDs are deduplicated; IDs not known by the supplied `OperationRegistry` are rejected. Enabling an operation does not authorize it as a solve move.

`OperationRuleEvaluator` is independent of `Window` and the live animation/scoring system. A UI request requires the current live input configuration (or the initial snapshot when no live state is supplied). If the operation is directly `SolveAllowed`, its plan costs one logical move. Otherwise, it may fall back to its validated Slide expansion only when Slide is `SolveAllowed`, and its move cost is the number of primitive moves. Scramble requests use only `ScrambleAllowed` and carry no solve move cost. Missing resolvers, malformed parameters, invalid expansions, and unauthorized requests produce rejected evaluations rather than partial mutations.

An accepted `OperationPlan` contains its intent, source-board snapshot, ordered primitive expansion, purpose, and accounting policy. `SessionRecordingController.ApplyOperation` revalidates the live board, input settings, mathematical rules and expansion before committing transactionally; the window updates the score only after success. Animation count remains independent from the plan's `MoveCost`.

The shared lens routes unmodified Shuffle and Ctrl-modified Swap gestures through the evaluator; Classic dragging keeps its existing behavior. Version 4 recordings persist operation parameters, the rule-set snapshot, accounting, and exact primitive expansions for deterministic replay; their external positional fields are one-based while internal intents and moves remain zero-based. Starting a recording snapshots current live inputs; changing them later does not rewrite it. Loading restores the saved initial inputs, while historical validation uses the recorded expansion and solve accounting rather than that initial input set. See [ShuffleLogic](ShuffleLogic.md) for controls and atlas mapping.

Open the command menu with Space and choose **Rules and Input Preferences**. The presets are Classic (Slide), ShuffleLogic (Shuffle), SwapLogic (ColumnSwap and RowSwap), TwoWide (Slide and ColumnSwap), TwoTall (Slide and RowSwap), Hybrid (Slide and Shuffle), ZeroSlide (Shuffle and both swaps), and FreeStyle (all four implemented operations). Each preset uses the same set for scrambling, solving, and its initial input configuration. TwoWide, TwoTall, Hybrid, and FreeStyle retain Slide fallback; ZeroSlide deliberately does not. Directly solve-allowed operations cost one logical move, while an operation enabled only as input falls back to Slide only when Slide is solve-allowed and then costs each primitive move.

Portable Lens operations require a board of at least 3 × 3. On smaller boards, lens-only presets are incompatible; presets that also permit Slide remain usable for Slide, and the Rules menu marks the lens choices unavailable. Rule changes require idle mode, preserve the board, and reset the run only when mathematical permissions change. Initial input preferences are saved in the recording snapshot; live input preferences can be changed independently without changing that snapshot or the rules. Custom rules are persisted in saved sessions, not as separate application-wide presets. Use arrows and Enter or the mouse in the menus; Escape closes them.

An ordinary lens drag requests Shuffle; Ctrl plus a horizontal or vertical lens drag requests ColumnSwap or RowSwap. Bindings are fixed in this version. Generated challenges use only the selected preset's ScrambleAllowed operations and are retained only when an inverse solution is verified under its SolveAllowed rules. Incompatible rules or board dimensions are rejected instead of claiming the board is solvable. Classic generation retains its existing behavior.
